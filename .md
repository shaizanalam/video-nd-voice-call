There is no completely free technology that allows video or voice calling between two countries without an internet connection or cellular network.

Video and voice data cannot travel thousands of kilometers directly between two phones. Data must either pass across physical cables/satellite routing (the internet) or telephone switching towers (cellular voice roaming).

Here is a breakdown of what does and does not work across international borders, along with the most cost-effective alternatives:

What Will Not Work
Offline P2P / Mesh apps (Bluetooth / Local Wi-Fi): Apps like MeshMeet or Walkie-Talkie work without internet, but only when devices are within 10 to 100 meters of each other. They cannot bridge the distance between India and Uzbekistan.

Standard VoIP (WhatsApp, FaceTime, Telegram): These require an active internet connection on both ends.

Realistic Workarounds for Very Weak or Spotty Internet
If the issue is low bandwidth / slow speed, rather than zero connectivity, standard video calls fail immediately. You can use tools optimized for poor networks:

Audio-Only Calling Over 2G/Low Speeds:

Signal or WhatsApp Voice (Low Data Mode): In WhatsApp, go to Settings > Storage and Data and turn on Use less data for calls. Audio requires only about 8–15 kbps, which often works even when video buffers completely.

Recorded Voice Notes: Instead of live streaming, asynchronous voice messages (WhatsApp, Telegram) cache automatically and send as soon as a 2G/3G signal briefly connects.

Wi-Fi Calling (VoWiFi) Using Her Indian SIM:

If she has an Indian SIM (Airtel or Jio) and connects to any local Wi-Fi in Uzbekistan, some Indian carriers allow Wi-Fi Calling without full international roaming packs, routing calls back to India as standard domestic calls.

Check: The phone must support VoWiFi, have the feature enabled in settings, and the carrier must support international VoWiFi on that plan.

Budget International VoIP-to-GSM Calling (Paid, but works with no internet on her end):

If you have internet in India but she has zero internet in Uzbekistan, apps like Skype Out, Viber Out, or Rebtel allow you to make a VoIP call from your phone that rings her phone as a regular cellular voice call on her local Uzbekistan SIM.

This is not free, but it avoids standard international STD/roaming rates and requires no internet on her side.

Local Mobile Data in Uzbekistan:

The simplest fix is getting a local Uzbekistan SIM card (such as Ucell, Beeline Uzbekistan, or Mobiuz) with a local prepaid data pack, or installing a travel eSIM (like Airalo or Nomad) if her phone supports eSIM. Once connected to a stable local 4G network, standard VoIP video calling will work seamlessly.

// Force Opus to mono, aggressive compression, and ultra-low bitrates
function modifySdpForLowBandwidth(sdp) {
  return sdp.replace(
    /a=fmtp:111 .*/,
    'a=fmtp:111 minptime=20;useinbandfec=1;maxaveragebitrate=6000;stereo=0;sprop-stereo=0;cbr=1'
  );
}
maxaveragebitrate=6000: Caps the audio to just 6 kbps (standard apps consume 32–64 kbps).

useinbandfec=1: Enables Forward Error Correction so dropped packets don't create robotic stutter.

cbr=1: Constant Bitrate helps prevent congestion on erratic connections.

NAT Traversal: Add a free STUN server (like Google’s public STUN stun:stun.l.google.com:19302) and a lightweight TURN relay (like a free tier on Metered.ca or Coturn on a cheap VPS) in case direct P2P is blocked by carrier firewalls.

Yes, WebRTC natively supports video calling alongside voice and arbitrary data transfer. In fact, video calling is one of its primary use cases—services like Google Meet, Discord, and WhatsApp Web all run on WebRTC under the hood.

Here is an architectural breakdown of how WebRTC works, how it handles video, and why it behaves differently on weak connections.

What Exactly Is WebRTC?
WebRTC (Web Real-Time Communication) is an open standard and browser API that allows two devices to exchange direct, real-time media streams (audio, video, data) peer-to-peer (P2P) without routing the heavy audio/video traffic through an intermediate media server.

Once a direct connection is established, the media flies straight from Phone A to Phone B over encrypted SRTP (Secure Real-Time Transport Protocol).

       [ Signaling Server (WebSocket / HTTP) ]
           /                               \
     (1. Exchange SDP & ICE Candidates)
         /                                   \
   [ Phone A (India) ] <==============> [ Phone B (Uzbekistan) ]
                     Direct P2P Encrypted Stream
                       (SRTP - Audio / Video)
How WebRTC Works: The 3 Core APIs
WebRTC exposes three core JavaScript interfaces in modern browsers:

getUserMedia(): Captures hardware media (camera and microphone streams).

RTCPeerConnection: The core engine. It manages the lifecycle of the connection, negotiates codecs, handles network jitter, implements packet loss concealment, and encrypts streams.

RTCDataChannel: Allows sending raw bidirectional text or binary data directly between peers with configurable reliability (TCP-like or UDP-like).

The Connection Lifecycle
To connect two devices across different countries and mobile carriers, WebRTC goes through three stages:

1. Signaling
Before two phones can talk directly, they must tell each other:

What codecs they support.

Their IP addresses and port numbers.

Because browsers cannot discover each other out of thin air, you use a tiny Signaling Server (usually a lightweight WebSocket server in Node.js or Python). Peer A creates an Offer (SDP), sends it via the server to Peer B, and Peer B responds with an Answer (SDP). Once this handshake completes, the signaling server can go idle; it doesn't touch the actual media stream.

2. NAT Traversal (STUN / TURN)
Cellular phones sit behind Carrier-Grade NAT (CGNAT) and firewalls, meaning they do not have public IP addresses.

STUN (Session Traversal Utilities for NAT): A STUN server simply answers: "Hey phone, here is what your public IP address and port look like to the outside world." Google provides public STUN servers for free (e.g., stun:stun.l.google.com:19302).

TURN (Traversal Using Relays around NAT): If both carriers use strict, symmetric NATs that block direct P2P connections, a TURN relay server acts as an encrypted fallback tunnel.

3. Media Streaming & Congestion Control
Once the P2P connection opens, the phones stream media over UDP. WebRTC continuously runs Google Congestion Control (GCC) to measure delay and packet loss, dynamically adjusting frame rate and resolution on the fly.

Does It Support Video? Yes, But Here Is the Reality for Weak Internet
WebRTC fully supports modern video codecs: VP8, VP9, H.264, and AV1.

However, video presents specific challenges when network speeds drop below 50–100 kbps:

Media Type	Typical WebRTC Bitrate	Minimum Threshold Before Failure	What Happens on 2G / Slow 3G
HD Video (720p)	1.2 Mbps – 2.5 Mbps	~800 kbps	Complete freeze / failure
Standard Video (360p)	300 kbps – 500 kbps	~150 kbps	Severe stutter, high latency
Ultra-Low Video (144p @ 5-10 fps)	30 kbps – 60 kbps	~25 kbps	Grainy and choppy, but functional
Optimized Opus Audio	6 kbps – 12 kbps	~4 kbps	Smooth voice; minimal packet loss

If you build your own WebRTC app and want video alongside voice, you have full control over the camera stream before it enters the encoder:

WebRTC has a property called degradationPreference:

This flexibility is why creating a tailored WebRTC interface works where off-the-shelf apps fail: you can explicitly sacrifice video resolution down to 144p or 5 fps so the audio connection never disconnects.

const express = require('express');
const http = require('http');
const { Server } = require('socket.io');
const path = require('path');

const app = express();
const server = http.createServer(app);
const io = new Server(server, {
  cors: { origin: "*" },
  pingTimeout: 60000, // Resilient against high latency spikes
  pingInterval: 25000
});

app.use(express.static(path.join(__dirname, 'public')));

io.on('connection', (socket) => {
  console.log(`[CONNECTED] Peer ID: ${socket.id}`);

  socket.on('join-room', (roomId) => {
    const room = io.sockets.adapter.rooms.get(roomId);
    const numClients = room ? room.size : 0;

    if (numClients === 0) {
      socket.join(roomId);
      socket.emit('room-created', roomId);
    } else if (numClients === 1) {
      socket.join(roomId);
      socket.emit('room-joined', roomId);
      socket.to(roomId).emit('peer-ready');
    } else {
      socket.emit('room-full');
    }
  });

  // Relay WebRTC SDP Offers, Answers, and ICE Candidates
  socket.on('signal', (data) => {
    socket.to(data.roomId).emit('signal', data);
  });

  socket.on('disconnecting', () => {
    socket.rooms.forEach((roomId) => {
      if (roomId !== socket.id) {
        socket.to(roomId).emit('peer-disconnected');
      }
    });
  });
});

const PORT = process.env.PORT || 3000;
server.listen(PORT, () => {
  console.log(`Signaling Server running on port ${PORT}`);
});

    async function applySenderBitrateLimits() {
      const mode = document.getElementById('mode-select').value;
      const profile = PROFILES[mode];
      const senders = peerConnection.getSenders();

      for (const sender of senders) {
        if (!sender.track) continue;
        const params = sender.getParameters();
        if (!params.encodings || params.encodings.length === 0) {
          params.encodings = [{}];
        }

        if (sender.track.kind === 'video' && profile.videoBitrate > 0) {
          params.encodings[0].maxBitrate = profile.videoBitrate;
          params.encodings[0].maxFramerate = 10;

          params.encodings[0].networkPriority = 'high';
